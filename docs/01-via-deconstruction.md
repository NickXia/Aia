# Via 浏览器拆解

> 一句话结论：**Via 不是"功能少的浏览器"，而是"默认界面只留一条工具栏、把所有复杂度折叠进设置"的浏览器。**
> 它的极简是**默认态极简**，不是能力极简——这是最容易学错的地方。

## 1. 它当初要解决的是什么问题

2018 年前后的国产安卓浏览器，商业模式几乎都是**信息流变现**：首页塞新闻卡片、推送、天气、小说入口。用户想做的其实只是"输个网址、看个网页"，却要先穿过一屏别人的内容。

Via 的赌注很单纯：**把首屏还给地址栏**。官网把 Mies van der Rohe 的「Less is more」直接写在产品特性里，不是文案修辞，而是它的取舍依据——任何"能提升停留时长但不服务浏览"的东西，一律不做。

这个赌注被验证了：8 年持续更新、千万级下载、"体积小 / 启动快 / 界面干净 / 可自由换搜索引擎"是被反复提到的评价关键词。

## 2. 四条产品信条（官网原文）

| 信条 | 官网措辞 | 实际落到什么 |
| --- | --- | --- |
| 快速高效 | "好事无需等待……效率至上的信条" | 毫秒级启动、低内存；不自带内核所以没有内核加载开销 |
| 极简主义 | "信息爆炸的今日，我们仍旧相信，浏览本该纯粹简单" | 首屏只有标识 + 搜索框 + 收藏图标；无新闻、无推送、无推荐位 |
| 隐私保护 | "强大的广告拦截，阻止追踪器，禁用第三方 Cookie" | 三项开关摆在设置一级入口；无痕模式；权限按需申请 |
| 无限可能 | "广告拦截、油猴脚本支持、主页自定义、网站设置" | 这是它的第二条腿：极简的界面 + 极客级的可配置性 |

**注意第 2 条和第 4 条是矛盾的，Via 用「默认值 vs 配置项」化解了**：默认值服务 80% 只想安静上网的人，配置项服务 20% 想把浏览器改成自己形状的人。两者共用同一套 UI 骨架，所以界面没有因此变复杂。

## 3. 2.5 MB 是怎么来的（架构决定，不是压缩技巧）

1. **不自带内核**，直接复用系统 WebView。整个 Chromium 的体积（100 MB+）省掉了。
2. **不预置内容**：没有新闻源、没有首页运营位、没有离线资源包。
3. **不集成第三方 SDK**：没有广告 SDK、没有推送 SDK、没有数据统计 SDK。
4. **权限按需申请**：平时只要网络，下载时才要存储、扫码时才要相机。

代价官方自己在 FAQ 里写明了：**渲染能力与网页兼容性受系统 WebView 版本限制**（可以单独升级 WebView 缓解）。也就是说 Via 用"把内核维护责任交给系统"换来了体积与启动速度。

> 对 Aia 的直接启示：鸿蒙上对应的就是 **ArkWeb 系统内核**。这条路不是"偷懒"，而是这个产品形态的第一性选择。任何"自己打包内核"的想法都会让 Aia 变成另一个物种。

## 4. 界面模型（最该学的部分）

### 4.1 布局：四种模式，默认只有一条常驻栏

| 模式 | 形态 | 适用 |
| --- | --- | --- |
| 传统（三明治） | 上下各一条工具栏 | 习惯双栏的老用户、平板 |
| 简洁 · 顶部 | 全部控件集中在顶部一条 | 单手够不到底部的大屏 |
| 简洁 · 底部 | 全部控件集中在底部一条 | **主流选择**，拇指可达 |
| 标签栏 | 可选常驻标签栏 | 多标签重度用户 |

关键不在于有几种模式，而在于**默认只显示一条**，主界面上没有第二排图标、没有标题栏、没有底部导航。

### 4.2 工具栏自动隐藏：三档

- **常显**：一直可见
- **滚动隐藏**：下滑收起、上滑回来
- **点击隐藏**：点屏幕切换显隐

这是"把屏幕让给内容"的具体手段，而不是靠做更小的按钮。

### 4.3 按钮是可编程的

- 工具栏按钮可**拖拽排序、增删**
- 每个按钮可单独绑定**长按动作**
- 可绑定的动作是一张统一的表：无操作 / 刷新 / 回到顶部 / 滑到底部 / 输入网址 / 打开书签 / 打开历史 / 关闭标签 / 上一个标签 / 下一个标签 / 后退 / 前进

### 4.4 手势 = 同一张动作表

屏幕滑动手势可以直接绑定上面那 12 种动作里的任意一种。**按钮、长按、手势、甚至是外接键盘的快捷键，全部映射到同一套 Action 枚举**——这是 Via 能同时做到"界面极简"和"高度可定制"的工程秘密：UI 只是 Action 的一种触发方式。

### 4.5 主页

标识 + 搜索框 + 收藏图标墙（约 7–8 个）。可自定义：背景色/背景图、图标风格（偏文字 / 偏图标）、图标配色（彩色 / 透明）。**没有信息流。**

### 4.6 设置层级

一级设置下分：通用（搜索引擎、站点配置、脚本、UA）、界面（布局模式、工具栏、夜间模式、地址栏样式、主页外观）、工具栏与手势、广告拦截（规则订阅）、隐私与安全、关于（点标识看 WebView 调试信息）。层级不深，但项数很多——复杂度被收进了这里。

## 5. 能力清单（按用户价值分层）

| 层 | 能力 |
| --- | --- |
| 浏览核心 | 多标签、书签、历史、下载管理、页内查找、网页翻译、请求桌面版网站（UA 切换）、网页源码查看 |
| 效率 | 多搜索引擎快速切换、离线保存网页、稍后读、扫码、外部应用跳转控制 |
| 隐私 | 广告拦截（兼容 Adblock Plus 规则、可订阅更新、可长按标记元素）、防追踪、禁第三方 Cookie、无痕模式、一键清数据 |
| 极客 | 用户脚本（油猴格式，内置编辑器，自动更新）、资源嗅探（抓页面里的音视频）、站点级配置（JS / 图片 / 剪贴板 / 弹窗 / 定位 / 摄像头 / 打开外部应用 逐站开关）、键盘快捷键、设置导入导出、WebDAV / 云同步 |

**隐私与极客这两层是它的护城河**，也是"体积小但功能不少"这个口碑的来源：功能密度高，但默认一个都不挡在你面前。

## 6. 代价与边界（不能装作没有）

- **闭源**，无法审计实现，也无法被社区接管。
- **iOS 版明显弱于安卓版**：WebKit 内核限制，很多安卓侧能力（脚本、嗅探）在 iOS 上并不完整。
- **不支持 Chrome 扩展（CRX）**，只有油猴脚本这一条扩展路径。
- **不做密码管理**：官方 FAQ 解释是 Google 从 WebView 里移除了该能力，只能靠系统自动填充。
- **能力天花板由系统 WebView 决定**，老系统上的网页兼容性会落后。
- **极简有学习成本**：默认藏起来的功能，新用户可能根本不知道存在。

## 7. 谁在用它

1. **老机型 / 存储紧张**：2.5 MB、低内存，是能救活旧手机的选择。
2. **信息流厌恶者**：不要推送、不要推荐、不要首页运营位。
3. **极客**：脚本、嗅探、逐站权限、快捷键——把浏览器当工具改装。

---

## 8. 照搬什么，不照搬什么

**可以照搬（结构性经验）**

1. 单行工具栏 + 其余全部折叠进菜单/面板。
2. 系统内核，不打包 Chromium。
3. **Action 统一抽象**：按钮、长按、手势共用一张动作表。
4. 默认值克制、配置项齐全，两者共用同一 UI 骨架。
5. 主页只做入口（搜索 + 收藏墙），不做内容。
6. 隐私开关是一级可见的开关，不是承诺文案。

**不能照搬（形态不同）**

1. **2.5 MB 体积竞赛**：ArkTS 应用的最小包体结构与 Android 不同，追求这个数字没有意义，追求"启动 0.3 秒、首屏无等待"才有意义。
2. **油猴脚本生态**：鸿蒙侧要自己搭 JS 注入沙箱，安全模型和 Android WebView 不一样，属于 v2 议题。
3. **WebDAV / 云同步**：涉及账号与合规，v1 不做。
